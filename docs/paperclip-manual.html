Todos os exemplos usam o binário paperclipai. Sem instalação, prefixe com npx. Valores entre <> são seus.

Paperclip é um plano de controle para uma empresa operada por agentes de IA. Ele não substitui o Claude Code, o Codex ou o Gemini CLI. Ele fica acima deles: cria a organização, distribui tarefas, acorda cada agente quando há trabalho, mede o gasto e exige aprovação humana antes de decisões caras. O produto é a empresa. Os adapters são a mão de obra.

Uma regra organiza tudo o que vem a seguir: o CLI não executa o modelo. Quando você digita um comando, o servidor Paperclip recebe uma chamada de API, roda o adapter do lado dele e devolve eventos e logs para o seu terminal. Você rege. O servidor toca.

Você, o Board
Terminal ou UI

Cria empresa, contrata agentes, aprova, ajusta orçamento, lê logs.

──── API ────>issues, wakeups, aprovações
Servidor Paperclip
Runtime e adapters

Acorda o agente, roda Claude ou Codex, registra runs, custos e atividade.

01

Instalar o CLI e verificar o Node

resultado: paperclipai --version responde

O CLI é um programa Node e exige a versão 24.11 ou mais nova. Versões 22 e 23 imprimem aviso e seguem, mas aviso não é suporte. Confira antes de qualquer outra coisa.

# precisa reportar v24.11.0 ou superior
node --version

Para experimentar, o caminho sem instalação é o npx. Para ficar, use a instalação gerenciada: ela baixa a release, verifica, instala em ~/.local/bin e passa a permitir update, rollback instantâneo e serviço em background.

# experimentar
npx paperclipai --help

# ficar: instalação gerenciada em ~/.paperclip/cli
npx paperclipai install
paperclipai --version
paperclipai channels        # stable · beta · nightly · canary
Nota

A instalação gerenciada guarda os dois payloads anteriores. Se uma atualização quebrar algo, paperclipai update --rollback volta na hora, sem download.

02

Subir a instância local

resultado: GET /api/health responde no localhost:3100

Dois comandos separam uma máquina vazia de um servidor saudável. O onboard grava a configuração, o segredo JWT dos agentes e a chave local de secrets. O run valida tudo com o doctor, repara o que souber reparar e só então sobe o servidor.

paperclipai onboard          # Quickstart: Postgres embutido, disco local, secrets criptografados
paperclipai run              # doctor + servidor

Em scripts e CI, aceite os padrões sem prompt. Sem --bind, isso força o modo loopback confiável.

paperclipai onboard --yes
paperclipai onboard --bind lan       # expor na rede local
paperclipai run --instance dev       # segunda instância isolada
paperclipai run --no-repair          # doctor só reporta

Deixe rodando

Um terminal fechado derruba o servidor. Entregue a tarefa ao sistema operacional: launchd no macOS, systemd de usuário no Linux, sem sudo.

paperclipai service install
paperclipai service status
paperclipai service logs --follow
paperclipai service restart          # hot restart: runs em andamento são adotados
Atenção

O run sem subcomando sobe a instância. Os subcomandos run list, run live e run log inspecionam heartbeat runs pela API. São dois conceitos sob o mesmo verbo.

Onde as coisas ficam, na instância padrão:

DadoCaminho
Config~/.paperclip/instances/default/config.json
Banco embutido~/.paperclip/instances/default/db
Logs~/.paperclip/instances/default/logs
Chave de secrets~/.paperclip/instances/default/secrets/master.key
03

Conectar e escolher quem você é

resultado: paperclipai whoami mostra persona board

Toda chamada ao plano de controle é feita como alguém. Existem exatamente duas personas e dois tipos de credencial.

PersonaAutoridadeCredencial
BoardToda a instância: todas as empresas, todos os agentes.Board API token. Nomeado, com expiração e revogação.
AgentUma empresa e um agente. Só pode agir como ele mesmo.Agent API key. Texto mostrado uma única vez.

Com um terminal na frente, o assistente resolve tudo: encontra o servidor, testa a saúde, faz login como board, deixa você escolher a persona, cunha um token, salva um perfil e imprime os exports.

paperclipai connect
paperclipai auth whoami

O perfil salvo em ~/.paperclip/context.json nunca guarda o token. Ele guarda o nome da variável de ambiente que contém o token. O segredo fica no seu shell ou no seu cofre.

paperclipai context set --api-base http://localhost:3100 \
  --persona board --api-key-env-var-name PAPERCLIP_API_KEY --use
export PAPERCLIP_API_KEY=...

Ordem de resolução

Quando um comando conecta no lugar errado, é sempre esta fila. A primeira fonte preenchida vence.

--api-base›PAPERCLIP_API_URL›perfil›porta do config›localhost:3100
Uma vez só

Tokens e chaves aparecem em texto claro apenas no momento da criação. Não existe comando para mostrar de novo. Capture na hora.

04

Criar a empresa e declarar o porquê

resultado: company list mostra sua empresa com prefixo

A empresa é o contêiner de agentes, projetos, metas, issues e orçamento. Dê a ela um prefixo curto: ele nomeia toda issue daqui em diante. Defina o orçamento mensal em centavos desde o primeiro dia.

paperclipai company create \
  --payload-json '{"name":"Acme","issuePrefix":"ACME","budgetMonthlyCents":500000}' --json

# guarde o id para os próximos passos
export PAPERCLIP_COMPANY_ID=<company-id>
paperclipai company current

Metas ficam acima do trabalho. Projetos e issues pendem de metas, não o contrário. Uma meta pode ter meta-mãe e um agente responsável.

paperclipai goal create --title "Alcançar lucratividade" --level company --json
paperclipai goal create --title "Lançar plano pago" --parent-id <goal-id>

paperclipai project create --name "Lançamento do site" \
  --goal-ids <goal-id> --status planned
Regra

Uma issue sem meta herda a meta do projeto; sem projeto, herda a meta padrão da empresa. Preencha as metas antes das issues e o gráfico de custo por objetivo sai de graça.

Na interface

As rotas da UI usam o prefixo de issues, não o id da empresa: o dashboard da Acme fica em http://localhost:3100/ACME/dashboard, as tarefas em /ACME/issues, os agentes em /ACME/agents/all.

05

Contratar o primeiro agente, o CEO

resultado: agent list mostra um agente ativo com orçamento

Toda empresa começa por um CEO. Ele fica no topo da árvore de reporte e pode, se você permitir, contratar os demais. Antes de montar o payload, leia o schema do adapter: ele diz exatamente quais campos a configuração aceita.

paperclipai adapter list
paperclipai adapter config-schema claude_local --json
paperclipai agent create --payload-json '{
  "name": "CEO",
  "role": "ceo",
  "adapterType": "claude_local",
  "budgetMonthlyCents": 150000
}' --json

Instruções vivem num bundle gerenciado no servidor, com a convenção de quatro arquivos: AGENTS.md para o papel, SOUL.md para o tom, HEARTBEAT.md para o que fazer ao acordar, TOOLS.md para ferramentas.

paperclipai agent instructions-file:put <agent-id> \
  --path AGENTS.md --content-file ./ceo/AGENTS.md

Antes de soltar

A ordem que evita sustos ao operar sem supervisão: política de orçamento, teto da empresa, folga por agente, conferência.

  • Orçamento mensal da empresa definido no passo anterior
  • Política de janelas: budget policy:upsert
  • Folga individual: budget agent:update <agent-id>
  • Conferir: budget overview e cost window-spend
Governança

Aos 80% do orçamento o Paperclip avisa; aos 100% ele para o agente. Agentes importados de pacotes chegam com o timer desligado, para nada gastar antes da sua revisão.

Para rodar Claude ou Codex localmente como esse agente, um comando cunha a chave, instala as skills em ~/.claude/skills e imprime os exports.

paperclipai agent local-cli ceo --company-id $PAPERCLIP_COMPANY_ID
06

Delegar trabalho como tarefa, não como chat

resultado: uma issue em todo, atribuída, e o agente acordado

O comando mais direto para dizer “vai fazer isto” é o prompt handoff. Ele cria uma issue em todo, atribui ao agente e o acorda. Não há resposta em streaming, não há sessão aberta. O trabalho acontece no servidor, no próximo heartbeat, e você o observa pela issue.

paperclipai board prompt --agent ceo \
  "Defina a estratégia do trimestre e abra as issues iniciais para cada meta"

Rodar o mesmo comando três vezes gera três tarefas separadas. Para continuar um trabalho existente, aponte a issue: o texto vira comentário e o agente é acordado contra ela.

paperclipai board prompt --agent ceo --issue ACME-12 \
  "O banco de staging voltou. Repita a migração e confirme as contagens."

paperclipai board prompt --agent ceo --no-wake "Auditar permissões não usadas"   # só enfileira

O ciclo de uma issue

backlog›todo›in_progress›in_review›done·blockedcancelled

Um agente reivindica trabalho com checkout atômico. O checkout só passa se a issue estiver num estado esperado, o que impede dois agentes de pegarem a mesma tarefa.

paperclipai issue checkout ACME-12 --agent-id <agent-id>
paperclipai issue update ACME-12 --status in_review --comment "Pronto para revisão"
paperclipai issue release ACME-12
Nunca repita

Um 409 no checkout significa que outro run já reivindicou a issue. A resposta correta é seguir para outra tarefa, não tentar de novo.

07

Observar o que o agente fez

resultado: você lê o log de um run e as issues que ele tocou

O dashboard responde “como está a empresa” numa chamada só: agentes ativos, trabalho aberto, gasto do mês, aprovações pendentes. Os comandos de run respondem “o que aconteceu neste heartbeat”.

paperclipai dashboard get --json | jq '.costs.monthUtilizationPercent, .pendingApprovals'

paperclipai run live --min-count 5
paperclipai run get <run-id>
paperclipai run events <run-id> --limit 50
paperclipai run log <run-id> --text
paperclipai run issues <run-id>

Quando o agente rodou um build ou um teste num workspace de execução, o erro real costuma estar no log da operação, não no log do run.

paperclipai run workspace-operations <run-id>
paperclipai run workspace-log <operation-id> --text
paperclipai run cancel <run-id>              # não desfaz o que já foi feito

A trilha de auditoria registra quem fez o quê em cada entidade. Para uma única tarefa, o atalho aceita o identificador humano.

paperclipai activity issue ACME-12
paperclipai activity list --agent-id <agent-id>
Watchdog

O servidor sinaliza runs que parecem travados. Antes de decidir, leia o log: uma suíte de testes longa é idêntica a um travamento até você olhar. Depois, run watchdog-decision <run-id> --decision continue --reason "...".

08

Governar custo e decisões

resultado: fila de aprovações vazia e orçamento sob controle

Aprovações são a camada entre o que um agente quer fazer e o que ele pode fazer. Contratar outro agente, fixar a estratégia do CEO e estourar orçamento passam por aqui. A persona que decide é sempre o board.

paperclipai approval list --status pending
paperclipai approval get <approval-id> --json

paperclipai approval approve <approval-id> --decision-note "Orçamento liberado."
paperclipai approval request-revision <approval-id> \
  --decision-note "Restrinja o papel a backend e reenvie."
pending›approved·rejected·revision_requested›resubmit

Quando o gasto ultrapassa uma guarda, o servidor abre um incidente e o trabalho afetado fica bloqueado até você resolver. A triagem que funciona:

  • cost window-spend para ver o quanto passou
  • cost by-agent para achar a origem
  • Ajustar com budget agent:update ou budget policy:upsert
  • Só então budget incident:resolve <incident-id>
Ordem importa

Resolver o incidente sem ajustar a política limpa o bloqueio e o incidente volta no próximo run.

Em emergência, uma chave desliga toda a automação de uma empresa na instância local, direto no banco, mesmo com o servidor fora do ar. Não existe “ligar tudo”: cada rotina volta uma a uma.

paperclipai routines disable-all --company-id $PAPERCLIP_COMPANY_ID
09

Automatizar e estender

resultado: uma rotina agendada e uma skill anexada ao agente

Rotinas são trabalho recorrente ou disparado por evento. Cada uma carrega um payload, um status, histórico de revisões e gatilhos por cron, webhook ou API pública. Duas configurações do gatilho merecem decisão consciente: concorrência, quando a próxima execução vence e a anterior ainda roda, e catch-up, o que fazer com janelas perdidas durante uma queda.

paperclipai routine create --payload-json '{
  "name": "Resumo noturno", "status": "active",
  "description": "Resumir as issues fechadas no dia"
}' --json

paperclipai routine trigger:create <routine-id> \
  --payload-json '{"kind":"schedule","schedule":"0 7 * * *"}'
paperclipai routine run <routine-id>        # dispara agora, para testar
paperclipai routine runs <routine-id>

Skills

Uma skill é uma pasta com SKILL.md: um procedimento repetível que o agente carrega sem você reescrever o prompt. Instalar na biblioteca da empresa e anexar ao agente são operações distintas. O modo é obrigatório e evita que um replace acidental apague o conjunto.

paperclipai skills browse --kind bundled
paperclipai skills install github-pr-workflow
paperclipai skills agent sync ceo --skill github-pr-workflow --mode add

Times prontos

O catálogo traz grupos completos: agentes, projetos, tarefas e as skills que precisam. Visualize antes, escolha o adapter de cada agente na instalação e encaixe o time sob um gestor que já existe.

paperclipai teams preview product-engineering --target-manager-slug ceo
paperclipai teams install product-engineering \
  --target-manager-slug ceo --adapter-override senior-coder=claude_local

Levar a empresa com você

Uma empresa é portátil. A exportação escreve uma pasta de arquivos markdown com manifesto e anexos; a importação lê de volta de um caminho, um zip ou um repositório GitHub, sempre com preview antes de escrever. É também o backup.

paperclipai company export $PAPERCLIP_COMPANY_ID --out ./exports/acme \
  --include company,agents,projects,issues,skills

paperclipai company import ./exports/acme --target new \
  --new-company-name "Acme (restaurada)" --dry-run
Disciplina de script

Credenciais explícitas, --json em todo comando, set -euo pipefail no topo. Um 401 ou 409 interrompe o script em vez de seguir com dados vazios.

A

Windows e problemas comuns

resultado: uma instalação real no Windows, do erro ao primeiro run

Tudo abaixo aconteceu numa instalação de verdade em Windows 11 com PowerShell 5.1 e Node 24. São os tropeços na ordem em que apareceram, com a saída correta para cada um.

Não existe serviço em background no Windows

O doctor avisa que gerenciamento de serviço não é suportado em win32. O servidor vive na janela do PowerShell: fechar a janela derruba o servidor, e cada nova sessão começa com npx paperclipai run. Para parar, use Ctrl+C dentro da janela. Fechar a janela sem isso é o que produz o problema seguinte.

“pre-existing shared memory block is still in use”

Sintoma: o log avisa que a porta 54329 está em uso, tenta a 54330 e o Postgres embutido recusa. Causa: um postgres.exe de uma sessão anterior continua vivo segurando o diretório de dados. O filtro por nome não basta, porque uma instalação separada do PostgreSQL também se chama postgres. Mate pelo dono da porta:

# PowerShell, tudo numa linha
Get-NetTCPConnection -LocalPort 54329,54330 -State Listen -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force -ErrorAction SilentlyContinue };
Start-Sleep -Seconds 3;
Remove-Item "$env:USERPROFILE\.paperclip\instances\default\db\postmaster.pid" -ErrorAction SilentlyContinue;
npx paperclipai run
Acesso negado

Erros de “Acesso negado” ao encerrar postgres ou pg_ctl costumam vir de um PostgreSQL instalado como serviço do sistema. Deixe-os em paz: se o servidor subiu na porta 54329 logo depois, o órfão certo foi encerrado.

Aspas em JSON no PowerShell 5.1

O PowerShell clássico remove as aspas duplas de dentro de um argumento antes de entregá-lo ao Node, e o JSON chega quebrado. Escape cada aspa com barra invertida dentro de aspas simples:

npx paperclipai company update $env:PAPERCLIP_COMPANY_ID `
  --payload-json '{\"budgetMonthlyCents\":5000}'

“required option -C, --company-id not specified”

Alguns comandos, como agent list, exigem o -C explícito mesmo com PAPERCLIP_COMPANY_ID exportado. Passe -C $env:PAPERCLIP_COMPANY_ID e siga.

Agente em error com “Authentication required”

O adapter claude_local executa o Claude Code na sua máquina e lê a credencial gravada pelo login dele. Sem login, todo heartbeat falha em três segundos com acpx_turn_failed, o agente entra em error e a issue vai para blocked. O comando claude pode nem estar no PATH quando o que existe é o app de desktop ou a extensão do VS Code.

# instala o CLI se faltar, abre o Claude Code; dentro dele: /login, depois /exit
if (-not (Get-Command claude -ErrorAction SilentlyContinue)) { npm install -g @anthropic-ai/claude-code }; claude

Depois do login, não é preciso reiniciar o servidor. Dê orçamento ao agente, reabra a issue e acorde-o contra ela:

$A="<agent-id>"
npx paperclipai budget agent:update $A --payload-json '{\"budgetMonthlyCents\":3000}'
npx paperclipai issue update LAB-1 --status todo
npx paperclipai agent wake $A -C $env:PAPERCLIP_COMPANY_ID `
  --reason "Login concluido" --payload '{\"issueId\":\"<issue-id>\"}'
npx paperclipai run live -C $env:PAPERCLIP_COMPANY_ID --min-count 2

Orçamento zerado não é guarda

Uma empresa recém-criada pela UI pode vir com budgetMonthlyCents: 0 e sem políticas. Isso não impede gasto; apenas não avisa. Defina o teto da empresa e o de cada agente antes do primeiro run, como no passo 05.

Aviso sobre master.key

O doctor sugere chmod 600, que não existe no Windows. O equivalente:

icacls "$env:USERPROFILE\.paperclip\instances\default\secrets\master.key" /inheritance:r /grant:r "$env:USERNAME:(R,W)"
