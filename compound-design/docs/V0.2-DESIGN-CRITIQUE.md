# Compound Design v0.2 — Design Critique

## Question

What should evolve after v0.1: more resources, better resources, or better evidence?

## Divergence

### Direction A — expand the catalog
Add many agents/skills immediately.

Pros:
- visible breadth;
- more apparent capability.

Risks:
- duplicated responsibilities;
- weaker routing;
- more maintenance;
- sophistication without proof.

Decision: reject for v0.2.

### Direction B — polish only
Improve the public narrative and visual presentation.

Pros:
- easier to explain;
- stronger demo.

Risks:
- framework itself does not improve.

Decision: useful but insufficient.

### Direction C — evidence architecture
Improve existing resources, separate construction from evidence, add executable contract checks, and add only one missing domain.

Pros:
- fixes a real v0.1 ambiguity;
- creates a durable version mechanism;
- makes future claims falsifiable;
- keeps scope small.

Risk:
- less feature-count theater.

Decision: choose.

## Convergence

v0.2 ships five substantive changes:

1. **CDQI/CEL separation** — construction quality no longer pretends to be evidence.
2. **Resource hardening** — `cd`, `jakub`, `emi`, `cd-quality-gate`, `cd-resource-lab` receive sharper jobs, boundaries and outputs.
3. **AI Interaction Quality** — one new skill fills a real domain gap without adding another agent.
4. **E1 contract suite** — reproducible deterministic checks become the first executed evidence layer.
5. **POC evidence UI** — the demo shows version, construction and evidence separately.

## Explicit non-goals

v0.2 does not claim:
- controlled runtime uplift;
- Claude/Anthropic/OpenAI certification;
- external validation;
- statistical significance;
- E2+ evidence.

## Exit criterion

v0.2 is complete when:
- the contract suite passes for every current resource;
- the release artifact records exact assertions;
- the POC exposes CDQI and CEL separately;
- deployment builds successfully;
- no expiring token is presented as the canonical URL.
